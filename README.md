# QDII Nav Tracker — 场外 QDII 基金持仓跟踪与净值预测

用**二十大持仓披露 + 全球股市日行情**预测场外 QDII 基金每日净值涨跌（披露覆盖率 48%→69%），验证持仓真实性，反推美股含量，并通过**滚动 NNLS 动态权重**追踪基金调仓。

每日北京时间 06:00 自动运行，由 Cloudflare Worker `qdii-dispatch` 定时调用 GitHub `workflow_dispatch` 触发（绕开 GitHub Actions schedule 共享队列偶发漏触发），产出报告到 `output/`，并渲染静态网页到 `docs/`（GitHub Pages 发布）。

## 核心方法

### 时间对齐规则（经实测验证）
- 净值日期 D 对应全球市场 **「交易日 ≤ D」最新收盘**（lag=0）
- 美东 T 日收盘 = 北京 T+1 日凌晨 → 北京 T+1 日晚公布净值（日期 T+1）
- 港股（北京 16:00 收）、A股（15:00 收）、日股/韩股（北京 8:00 开、14:30 收）均**当天收盘即计入当晚净值**（实测 corr 0.912 vs 前一日 0.500）
- 因此北京 06:00 运行时，可用美股 T 日收盘 + 日韩港 T 日收盘预测**今晚将公布**的净值涨跌

### 三通道分析（每只基金）
| 通道 | 方法 | 回答的问题 |
|---|---|---|
| 静态披露权重 | 二十大持仓占比 × 各市场日收益（美股/港股/A股/日韩，含 USDCNH 折算） | 披露持仓能否解释净值？（R²/方向一致率） |
| 滚动 NNLS 动态权重 | walk-forward 60日非负最小二乘（**仅持仓成分**，不含汇率，见踩坑 11） | 实际持仓与披露差多少？（疑似调仓） |
| 美股指数暴露 | 净值对 NDX 回归（近6月 β） | 实际美股含量多大？（NDX β） |

> **全市场参与预测**：美股/港股/A股（主板+创业板+科创板）/日韩股全部纳入静态权重篮子。净值日定价基准 = 美股 T 日凌晨收盘（美东 T-1）+ 日韩/港股/A股 T 日白天收盘，预测输入与基金公司估值完全对齐。
>
> **汇率只用于静态篮子**：静态项按 `wsum × 当日汇率变动` 折算（wsum = 持仓权重和 → 汇率敞口 = 持仓比例，经济含义明确）；**滚动 NNLS 不含汇率特征**（见踩坑 11）。

### 前瞻预测 + 自动验证闭环
- **每晚预测**：用美股最近收盘（统一 `us_last` 基准）预测当晚将公布的净值涨跌（静态披露权重 + 滚动NNLS 双预测），全部基金共用同一预测净值日，不因净值更新节奏不同而分裂
- **预测/验证分流**：基金最新净值日期 ≥ us_last → 该期已公布，走验证（显示预测 vs 实际对照）；< us_last → 生成新预测（待公布）
- **自动验证**：预测写入 `output/predictions.jsonl`，净值公布后自动回填 actual，统计方向命中率 / MAE，网页展示"历史预测验证"板块
- **方向背离提示**：预测方向与 NDX 指数当日收益相反时标注"⚠️与大盘背离"（卡片右上角显示 NDX 当日收盘点位+涨跌幅）

### 门控与参考值模式（provisional）

三道门控，按序判定：

| 门 | 判据 | 结果 |
|---|---|---|
| ① 美股交易日 | 美东昨日（北京视角）是否 NYSE 交易日 | 非交易日 → 跳过运行 |
| ② 目标净值日 | 美股最近收盘日 `us_last` 是否 A股交易日 | 非 A股日 → **参考值模式**（不再拦截） |
| ③ 长假回归保护 | 基金最新净值 ↔ `us_last` 间隔 ≥2 个美股交易日 | 正常模式跳过当日；参考值模式下跳过本检查 |

**参考值模式**（目标净值日非 A股交易日，如中秋/国庆期间）：该日基金不公布净值，预测**不对应任何真实净值**——仍照常运行并展示，但页面/报告/日志标注「⚠️ 参考值模式」，预测**不落库**（`append_predictions` 防御断言拦截：`pred_date` 非 A股交易日一律不写 `predictions.jsonl`）、**不参与验证统计**。判定与 `--force` 无关（手动补跑同样有标注）。

**休市日处理**（5 市场日历 NYSE/XHKG/XSHG/JPX/XKRX，`pandas_market_calendars`）：
- 休市市场成分收益**按 0 计**（价格确定没变），**保留权重**——不能当缺失剔除，否则会把该市场敞口摊给其他市场 → 放大预测
- 汇率按**中国日历**处理（非 A股交易日 → 当日汇率变动按 0，防中行牌价旧值冒充）
- 市场开市但行情序列未覆盖目标日（数据源滞后）→ 该成分**剔除 + 告警**（与"缺失"同走归一化）
- 缺口门控：依赖标的近 4 天存在未修复缺口 → 跳过该基金当日预测并告警（宁缺勿错）

### 精度评估体系（五维）
| 指标 | 定义 |
|---|---|
| 方向命中率 | sign(预测) == sign(实际) |
| **幅度命中率 ±1pp** | \|误差\| ≤ 1.0pp |
| **综合精度命中** | 方向对 且 \|误差\|≤1.0pp |
| **区间覆盖率** | 实际 ∈ 预测 ± 1.28×MAE 误差带（80%置信） |
| MAE / RMSE / bias | 误差统计（bias=平均误差，正=高估，供校准依据） |

- 所有 ✓/✗（验证表格、预测卡片）均为**综合命中**——方向对 且 |误差|≤1.0pp 才算 ✓（避免"猜对涨跌"掩盖"幅度不准"）
- 精度统计**只看 `pred_static`**（`verify_history` 的 `hit`/`err` 均由静态预测计算）——调整 NNLS 特征不影响命中率统计

## 本地运行

```bash
pip install -r requirements.txt
python scripts/run_daily.py --out output        # 正常（门控判断）
python scripts/run_daily.py --force --out output  # 强制运行（门①跳过，参考值标注仍在）
python scripts/render_html.py --json output/daily_report.json --history output/predictions.jsonl --holdings-full output/holdings_full.json --out docs/index.html
```

### 数据质量与交易日缺口补齐

`data_fetcher._repair_missing_days()` 对**以 yfinance 为主源的市场（美股/日韩）**做交易日完整性校验：

1. 用市场日历（NYSE/JPX/XKRX）算出序列覆盖区间内应有而缺失的交易日，以及值为 NaN 的空行；
2. **先查持久化缓存 `output/.gap_repair_cache.json`（`symbol|date → close`）**——历史交易日收盘价不可变，命中即 0 请求；
3. 未命中的按各市场补齐链联网补齐（同一源只请求一次，批量补多天）；
4. **源级熔断**：同一源连续 3 次补不到 → 本次运行不再尝试该源；
5. 补不到 → 以 **NaN 占位**（保留日期），并登记 `unresolved`；
6. 预测前检查依赖标的近 4 天是否有未修复缺口 → 有则**跳过该基金当日预测并告警**。

报告 `data_quality` 字段（`counts`{`found`/`repaired`/`from_cache`/`unresolved`} / `sources_disabled` / `gap_cache_entries`），运行日志与页面徽章（⚠️ 数据缺口 N）同步暴露。`repaired` 只统计本次由网络新补的，`from_cache` 为缓存复用数。

### 基金清单与特殊类型

> **基金清单配置化**：`config/funds.json` 驱动（可经本地维护面板 github-data-maintainer.html 编辑，或直接改文件提交）。**增减基金 → 下次 cron 自动生效**（卡片/走势图/验证/涨跌幅列全自动跟随）。当前 12 只：002891/008254/014002/015202/016702/018147/021277/021842/022184/080006/024239/017093。

> **持仓代理 `holdings_proxy`**：ETF 联接基金 / FOF 的 F10「股票投资明细」可能长期停更（真实持仓是持有的目标 ETF 份额）。在 config 里给该类基金加 `"holdings_proxy": "<目标ETF代码>"`，分析时**持仓取目标 ETF（穿透披露）、净值仍用基金自身**。实例：`017093 景顺纳科C → 159509`。

> **持仓期次校验**：解析 F10 最新报告期，若比「当前应已披露期」落后 >2 个季度 → 判定数据过期，**跳过该基金预测并告警**（防止持仓停更的基金静默产出错误预测）。

> **走势图颜色**：预定义调色板 + 固定色 + 按 code 排序补色 + 超限哈希色相兜底——新增基金自动拿到不重复颜色。

## 已知边界

- 二十大持仓覆盖基金仓位约 55~85%，剩余仓位影响会分摊进 NNLS 权重（看趋势、不直接当精确占比）
- 披露为季末时点，季末后调仓会降低静态 R²；半年报披露后可升级全持仓口径
- 幅度预测（MAE ~0.5-1.1pp）只能参考，方向预测（77~95%）更可靠；方向偏差源于"披露持仓≠实际持仓"，NNLS 能缩小但无法完全消除
- 参考值模式的预测值是「截至 us_last 收盘的累计变动」，**不与任何真实净值对应**（目标日无净值），也不能和后续回归首日的净值对比
- 腾讯快照兜底在"日韩已收盘+美股未收盘"窗口（北京 9:00-16:00）手动触发时可能跳过日韩股（已知边界，暂不处理）
- 数据源（尤其 Yahoo）出现「整行空值」的 K 线时，若东财/新浪/腾讯都补不到该交易日 → 相关基金当日**不出预测**（宁缺勿错），页面显示"⚠️ 数据缺口 N"
- `trading_day_set` 日历窗口向前 800 天：回测起点早于该窗口会导致日期被误判休市（见踩坑 13）

## 排错与踩坑记录

### 1. Yahoo 整行空值 K 线 → yfinance 静默丢行 → 交易日缺口

Yahoo 对某交易日返回整行空值的日K 时，yfinance `history()` 默认 `keepna=False` 会**静默丢弃**该行 → 序列出现交易日缺口 → "相邻两行=相邻交易日"的假设把**多日累计当单日**（实例：NDX 显示 -0.04%，实际 -0.85%）。

**现行机制**：① 所有 yfinance 调用统一走 `_yf_history(keepna=True)`；② `_repair_missing_days()` 按补齐链补齐，全失败 → NaN 占位 + 跳过该基金当日预测；③ 页面 NDX 涨跌幅直接取行情接口自带值；④ `asof_ret()` 缺口日返回 `NaN`（不静默回退到更早交易日）。

### 2. 东财 secid 地雷：`100.NDX` 不是纳斯达克100

`100.NDX` = 纳斯达克**综合**指数；纳斯达克100 必须用 `100.NDX100`。标普500 = `100.SPX`、道指 = `100.DJIA`。用错会得到"看起来很合理"的完全错误点位。

### 3. 腾讯美股日线必须带交易所后缀，且后缀**不能猜**

腾讯日线对美股**个股**必须带交易所后缀，否则只返回 1~2 条废数据。后缀不能靠猜：`usCIEN` 的正确码是 `CIEN.N`（NYSE），按 `.OQ` 先试会命中一个**混入 2014 年数据、且恰好缺目标交易日**的错误序列 → 静默写入错误收盘。

**正确做法**：先请求快照 `qt.gtimg.cn/q=us<CODE>`，用其 `[2]` 字段拿权威代码，再用它请求日线；指数（`usNDX`）无需后缀。**"看似成功但内容是错的"比"失败"危险得多**。

### 4. 东财 push2his 需 curl_cffi，且不能走代理

境内源直连：用 `requests` 会被 `RemoteDisconnected`，必须用 `curl_cffi`（`impersonate="chrome"`）；同时**不要给它挂代理**。

### 5. 本地 yfinance 常被限流 → 诊断用 Yahoo chart API 直连

家宽 IP 调 yfinance 常报 `YFRateLimitError`，云端 Actions IP 正常。本地排查数据问题时改用 `https://query1.finance.yahoo.com/v8/finance/chart/<symbol>?range=6mo&interval=1d`（需代理），可直接拿到原始 `meta.previousClose` / 每根 K 线。

### 6. CI 用 Python 3.11，f-string 不能嵌套同类引号

`f"{d['k']}"` 合法，但 `f"{[f'{g['symbol']}' for g in x]}"` 在 3.11 直接 `SyntaxError`（PEP 701 才放宽，3.12+）。写嵌套表达式前先赋给临时变量。

### 7. 给 CI 加"网络兜底链"会显著拖慢 Actions —— 必须配熔断

新增缺口补齐后分析步骤从 153s 涨到 479s（3.1 倍）：GitHub runner 出口 IP 对东财 push2his 大量限流，每次失败都带重试+休眠。

**教训**：往 CI 里加任何"失败再换源"的链，必须同时加**源级熔断** + **优先放云端稳定的源**（缺口补齐链里新浪优先：云端 22/22 成功 vs 东财 11/46）。**加机制前先量一次耗时**。

### 8. 报告写完之后抛异常 → workflow 的「Commit outputs」被跳过 → 结果全丢

`run_daily.py` 先写 `daily_report.json`，再打印数据质量汇总——汇总打印若抛异常，step 退出码 1，后续 Render/Commit 全被跳过，报告留在 runner 临时盘上什么都没提交，而日志里仍有 `DONE -> output/daily_report.json`，极易误判为成功。

**教训**：报告落盘之后的任何收尾代码都必须 `try/except` 包住。**判断 Action 是否真正成功，看步骤结论，不看日志里的 DONE**。

### 9. GitHub API 403 `Request forbidden by administrative rules`（缺 User-Agent）

GitHub REST API 强制要求 `User-Agent` header，缺失被 403 拒绝（错误信息藏在响应体里，光看状态码容易误判成 token 权限问题——token 无效是 401 不是 403）。Cloudflare Worker 的 `fetch` 默认不补 UA，需手动加。**排查技巧：让 worker 把上游响应体透传回来，别只看状态码猜**。

### 10. 「不落盘的缓存 = 没有缓存」：同一个历史缺口被每天重补

Yahoo 的空行是它侧的故障，`keepna=True` 保留后每次运行都会判定"有缺口"（判定必然为真，与运行频率无关）；补齐结果若只进进程内存，进程退出即丢 → 35 天窗口内天天重补同一批历史值（≈21 请求/天）。

**现行机制**：补齐结果落盘 `output/.gap_repair_cache.json`（键 `symbol|date`）——历史交易日收盘价不可变，缓存永久有效，第二次起 0 请求。

> **通用教训**：取"不会变的数据"（历史 K 线 / 已披露持仓 / 已结算净值）就必须落盘复用；只放进程内存等于没缓存。

### 11. 「有经济含义」≠「该进回归」：汇率在 NNLS 里的过拟合

**现象**：5/12 只基金的 NNLS 权重中汇率（FX）排第一，取值最高 8.6——而汇率敞口物理上限是 100% 持仓（权重 ≤1），`>1` 即经济不可能值。

**三条独立证据 → 判定为过拟合噪声**：
| 证据 | 结果 |
|---|---|
| A/B 回测（3 只基金，同算法） | 去掉 FX 后 MAE 不变或微降：0.816→0.816 / 0.991→0.930 / 0.651→0.648；方向命中不变 |
| 权重稳定性 | 同一基金云端权重 2.70 vs 本地同算法 0.0（不可复现）；024239 权重中位 6.86、97.9% 期数 >1 |
| 因子解释力 | `corr(中行牌价日收益, 基金净值日收益)` = 0.001~0.084（≈0）；两个权威汇率源日收益互相关仅 0.13 |

**现行机制**：`rolling_nnls` 不含汇率特征；汇率只在静态篮子（`wsum × fxr`，敞口 = 持仓比例，经济正确）。

> **通用教训**：因子"有经济含义"不等于"该进回归"。判据：① 去掉后回测是否变差 ② 权重是否稳定且在合理范围 ③ 与目标相关性是否显著。三者都不满足时它只是在拟合噪声。另：改模型前先确认"哪个字段在承重"——本项目精度统计只看 `pred_static`，故调整 NNLS 特征不影响验证逻辑。

### 12. 「双重记账」：同一次请求被记两次，指标虚高一倍

`_retry_call`（内层）与 `fallback_chain`（外层）对同一次 fetch 各记一次 → `数据源汇总` 里中行牌价显示 2 次/19.4s，实际 1 次/9.7s。

**现行机制**：`fallback_chain` 记账前比较 `_src_total()` 基线，仅内层未记账时补记。只改统计口径，不影响取数与预测。

> **通用教训**：包装器（retry/fallback）与被包装函数若**都做埋点**，统计必然翻倍。埋点只在一层做，或用基线比对判断内层是否已记。

### 13. 休市日「旧值冒充」：`asof_ret` 会拿前一交易日收益冒充目标日

**现象**：A 股中秋休市（2026-09-25），`asof_ret(9/25)` 对 A股成分返回 **9/24 的收益**（实例：600183 返回 −4.34%，实为 9/24）；中行牌价同样返回 9/24 的 +0.031%。根因：`asof_ret` 的语义是"取 ≤ D 的最近交易日收益"（本意处理披露滞后），**没有"该市场当天是否开市"的校验**——休市日必然旧值冒充，且是静默的。

**现行机制**（预测路径全链路修正）：
- `is_market_open(market, date)` / `market_open_mask()` 基于 5 市场权威日历判定开市；`trading_day_set` 日历窗口向前 **800 天**——窗口若只覆盖 420 天，起点晚于回测起点（2025-08-01）会导致**首日被误判休市、全部成分收益误置 0**（已实测复现，扩窗修复）
- 休市成分收益**按 0**（价格确定没变）、**保留权重**——当缺失剔除会把该市场敞口摊给其他市场 → 放大预测
- 汇率按中国日历（非 A股交易日 → 当日变动按 0）
- 开市但数据未到（源滞后）→ 剔除 + 告警（与"缺失"同走归一化）
- 历史回测同步受益：024239 修正后 R² 0.849→0.861、方向命中 88.4%→90.1%、滚动 MAE 0.99→0.93

> **通用教训**：① "asof/取最近"类函数对**休市日**天然返回旧值，必须有日历校验；② 休市 ≠ 缺失：休市是"价格确定没变"（按 0 保留权重），缺失是"不知道"（剔除+归一化），两者混用必然出错；③ **窗口边界要覆盖使用方的时间范围**——日历/缓存窗口的默认值若只够"眼前"用，回测/历史路径会静默踩空。
